# 小马哥发包 - 应用商店自动发布系统需求文档（PRD）

**版本**: v1.0  
**创建日期**: 2026-03-23  
**状态**: 已确认  

---

## 一、问题陈述

你管理多个APP，需要频繁更新到6个应用商店（小米、应用宝、华为、荣耀、OPPO、Vivo）。由于每个APP在不同开发者账号下，且同一APP在各商店的APK包不同，每次更新都需要手动切换登录多个账号提交，过程繁琐且容易出错。通过调用各应用商店提供的API，可以自动化此流程，显著提高效率。

---

## 二、目标

| 目标类型 | 具体目标 | 衡量方式 |
|---------|---------|---------|
| 效率提升 | 将单个APP更新6个商店的时间从30分钟缩短到5分钟 | 对比手动vs自动化的操作时间 |
| 错误减少 | 消除因切换账号导致的登录错误、APK上传错误 | 追踪更新失败率 |
| 可扩展性 | 支持新增APP或应用商店的快速接入 | 接入新商店所需开发时间 |
| 用户体验 | 提供可视化的更新状态追踪 | 用户满意度评分 |

---

## 三、非目标（明确不做）

| 非目标 | 原因 |
|-------|------|
| 支持APP首次发布（创建新应用） | 首次发布需要更复杂的资质审核流程，超出当前自动化范围 |
| 自动处理审核结果和反馈 | 各商店审核规则差异大，需要人工判断处理 |
| 对接全部6个应用商店（第一期） | 降低初期复杂度，先验证核心流程 |
| 多用户协作/权限管理 | 个人/小团队使用场景，暂不需要复杂权限系统 |
| APP数据统计分析 | 专注于发布管理，非运营分析 |

## 四、用户故事

### 核心用户故事

1. **作为** 应用开发者，**我希望** 在一个统一界面管理所有APP在各应用商店的更新，**以便** 不用频繁切换账号登录。

2. **作为** 应用开发者，**我希望** 为每个APP配置不同应用商店的APK包，**以便** 应对各商店的差异化要求。

3. **作为** 应用开发者，**我希望** 一键提交APP更新到指定应用商店，**以便** 快速完成发布流程。

4. **作为** 应用开发者，**我希望** 查看每个APP在各商店的更新状态，**以便** 了解发布进度。

### 第一期（仅小米）用户故事

5. **作为** 应用开发者，**我希望** 添加小米开发者账号并保存密钥，**以便** 后续自动调用API。

6. **作为** 应用开发者，**我希望** 选择APP和对应的小米渠道APK包进行更新，**以便** 自动推送到小米应用商店。

## 五、需求优先级

### P0 - 必须实现（第一期）

| 需求 | 描述 | 验收标准 |
|------|------|---------|
| 账号管理 | 添加/管理小米开发者账号（邮箱+私钥） | 可安全存储并用于API签名 |
| APP管理 | 添加/编辑APP基本信息和小米渠道配置 | 包含包名、当前版本、小米分类等信息 |
| APK上传 | 上传并关联APP的小米渠道APK包 | 文件大小≤2GB，自动提取版本信息 |
| 更新提交 | 调用小米API提交版本更新 | 支持版本更新(synchroType=1) |
| 状态查询 | 查询APP在小米商店的当前状态 | 显示当前版本、审核状态等 |

## 六、小米API对接技术要点

根据已保存的[小米API文档](./xiaomi-api-docs.md)，核心技术点：

1. **认证机制**：RSA数字签名，需要保存用户私钥并生成SIG
2. **关键接口**：
   - `POST /dev/query` - 查询APP当前状态
   - `POST /dev/category` - 获取应用分类列表
   - `POST /dev/push` - 提交APP更新（synchroType=1）
3. **必需字段**：用户邮箱、私钥、APK文件、图标、包名、版本信息
4. **错误处理**：需处理签名错误、包名不存在、APK格式不符等

## 七、数据模型设计建议

```
App（应用）
├── id, name, packageName（主包名）
├── iconUrl, currentVersion
└── Channels（渠道配置）
    ├── channelType: xiaomi/appbao/huawei...
    ├── accountId（关联的开发者账号）
    ├── apkPath（该渠道的APK路径）
    ├── categoryId（商店分类ID）
    └── extraConfig（各商店特有配置）

Account（开发者账号）
├── id, name
├── channelType: xiaomi
├── email（开发者邮箱）
├── privateKey（加密存储）
└── publicKey

ReleaseRecord（发布记录）
├── appId, channelId
├── versionName, versionCode
├── status: pending/success/failed
├── message（返回信息）
└── createdAt
```

## 九、风险与注意事项

1. **私钥安全**：用户的小米私钥需要加密存储，服务端不应明文保存
2. **API限制**：虽然小米文档说频率无限制，但仍需做好限流和重试
3. **审核流程**：自动化只负责提交，审核结果仍需人工关注
4. **测试策略**：小米无沙盒环境，测试后需要撤回测试提交
